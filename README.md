# 코토노하 (ことのは)

> 일본어 동아리원들이 각자 좋아하는 일본 노래에서 **마음에 든 가사를 모으고**, 그 가사로 공부하고, 게시판에서 감상을 나누는 커뮤니티 웹앱

고급웹프로그래밍 (React) 개인 포트폴리오 프로젝트

**노래 등록 → 가사 수집 → 단어장 자동 생성 → 복습 카드 → 게시판에서 감상 공유**

단어만 따로 외우는 단어장이 아니라, **내가 좋아하는 노래의 가사째로** 저장하고 노래별로 모이게 하는 것이 이 프로젝트의 차별점입니다.

---

## 실행 방법

```bash
npm install
npm run dev      # 개발 서버 실행 → http://localhost:5173
npm run build    # 배포용 빌드 (dist 폴더)
npm run preview  # 빌드 결과 미리보기
```

## 데모 계정

| 역할 | 아이디 | 비밀번호 | 닉네임 |
|---|---|---|---|
| 운영진 (공지 작성 가능) | `admin` | `admin123` | 소라 |
| 동아리원 | `mina` | `mina123` | 미나 |
| 동아리원 | `jun` | `jun123` | 준 |

로그인 화면의 데모 계정 버튼을 누르면 자동으로 입력됩니다.
데이터는 브라우저의 localStorage에 저장되며, 화면 맨 아래 **"샘플 데이터로 초기화"** 를 누르면 처음 상태로 돌아갑니다.

> ※ 샘플 노래, 가수, 가사는 저작권 문제를 피하기 위해 모두 직접 지어낸 가상의 것입니다.

## 기술 스택

- Vite + React 19 (함수형 컴포넌트)
- React Router v6: 중첩 라우팅, `<Outlet />`
- Redux Toolkit + React Redux
- CSS Modules와 전역 CSS 변수. UI나 차트 라이브러리는 쓰지 않았습니다.
- 서버 없음. Redux 상태를 localStorage에 저장합니다.

## 기능 목록

### 회원 (모의 로그인)
- 회원가입: 아이디, 닉네임, 비밀번호와 비밀번호 확인, 목표 JLPT 레벨
- 입력 검증: 빈 값, 아이디 형식, 아이디 중복, 비밀번호 불일치
- 로그인, 로그아웃, 새로고침 후 로그인 유지
- 로그인이 필요한 페이지는 `ProtectedRoute`로 보호합니다. 로그인하면 원래 가려던 페이지로 돌아갑니다.
- 역할: 운영진(admin)과 동아리원(member). 공지는 운영진만 쓸 수 있습니다.

### 플레이리스트 (노래)
- 노래 등록, 수정, 삭제: 일본어 제목, 한국어 제목, 가수, 장르(J-POP, 애니송, 보컬로이드), 상태, 가사 외운 정도(0~100). 노래를 삭제하면 그 노래의 문장도 함께 삭제됩니다.
- 상태별 필터(듣는 중, 완창, 들어볼 곡), 제목 검색(일본어/한국어)
- "내 노래"와 "전체 동아리원" 보기 전환
- 필터와 검색어는 주소(`?status=&scope=&q=`)에 저장되어 새로고침해도 유지됩니다.

### 문장 수집 (핵심 기능)
- 원문, 해석, 위치, 메모, 단어 목록(단어 줄을 추가하고 삭제할 수 있음)
- **히라가나**: 원문에 `{漢字|かんじ}`로 입력하면 한자 위에 읽는 법이 표시됩니다. 입력하는 동안 실시간 미리보기를 보여주고, 켜기/끄기 버튼도 있습니다.

### 마이페이지
- **단어장**: 내가 수집한 문장의 단어가 자동으로 모입니다. 검색할 수 있고, 단어를 누르면 그 단어가 나온 문장으로 이동해 해당 단어를 강조합니다.
- **복습 카드**: 앞면은 해석, 뒷면은 원문입니다. 클릭이나 Space로 뒤집고 ←/→ 키로 답합니다. "몰라요"를 누른 카드는 이번 회차 끝에 다시 나오고, 결과는 문장에 기록됩니다. 노래별 복습과 "몰라요였던 문장만" 복습도 할 수 있습니다.
- **통계**: 노래 수, 완창 수, 문장 수, 단어 수, 복습 정답률, 장르별·상태별 비율 막대(CSS로 구현)

### 게시판
- 카테고리: 공지, 감상, 번역 질문
- 글 작성, 조회(조회수 증가), 수정, 삭제, 제목 검색
- 댓글 작성과 삭제. 본인 글과 본인 댓글만 수정하거나 삭제할 수 있습니다.
- 삭제하기 전에 확인 모달을 띄웁니다. 모달은 ESC 키나 바깥 영역을 누르면 닫힙니다.

### 홈
- 오늘의 문장: 날짜별로 정해지고, "다른 문장" 버튼으로 무작위로 바꿀 수 있습니다.
- 이용 흐름 5단계 안내
- 동아리원들이 최근 수집한 문장 피드, 최근 게시글

### 기타
- 404 페이지, 데이터가 없을 때의 안내 화면(EmptyState)
- 반응형 레이아웃: 모바일에서는 햄버거 메뉴를 쓰고 1단으로 배치합니다.

## 라우트 구조 (중첩 라우팅)

```
/                         홈
/login, /signup           로그인, 회원가입
/songs                    플레이리스트
/songs/new                노래 등록 🔒
/songs/:songId            노래 상세 레이아웃 (노래 정보 고정 + Outlet)
  ├ (index)               수집 문장 목록
  ├ quotes/new            문장 추가 🔒
  └ quotes/:quoteId       문장 상세
/board                    게시판 레이아웃 (카테고리 탭 고정 + Outlet)
  ├ (index)               → /board/review
  ├ write                 글쓰기 🔒
  ├ :category             글 목록
  ├ :category/:postId     글 상세 + 댓글
  └ :category/:postId/edit 글 수정 🔒
/mypage                   마이페이지 레이아웃 🔒 (탭 고정 + Outlet)
  ├ vocab                 단어장
  ├ review                복습 카드
  └ stats                 통계
*                         404
```

## 폴더 구조

```
src/
├── store/        Redux store와 4개 slice (auth, songs, quotes, board)
├── data/         샘플 데이터 (seed.js)
├── hooks/        커스텀 Hook (useAuth, useDebounce)
├── utils/        localStorage 저장, 날짜·id 등 도우미 함수
├── components/
│   ├── layout/   Layout, Header, ProtectedRoute
│   └── common/   Button, Card, Modal, SearchBar, EmptyState, RubyText
├── features/     기능별 UI 컴포넌트 (Props로 데이터를 받고 이벤트를 부모에게 알림)
└── pages/        라우트 하나에 파일 하나 (Redux와 연결하는 곳)
```

## 설계에서 고민한 점

- **왜 Redux를 썼나**: 노래, 문장, 게시글, 회원 정보는 홈, 플레이리스트, 게시판, 마이페이지 여러 곳에서 함께 씁니다. Props로 계속 내려 주지 않고 하나의 저장소에 모았습니다.
- **pages와 features를 나눈 이유**: `pages`는 Redux에서 데이터를 꺼내고 action을 보내는 일을 맡고, `features`는 Props로 받은 데이터를 그리는 일만 맡습니다. 그래서 같은 `PostForm`을 글쓰기와 수정에서, 같은 `QuoteCard`를 노래 상세와 홈 피드에서 다시 쓸 수 있었습니다.
- **4개 slice의 같은 패턴**: 모든 slice가 추가(prepare에서 id와 날짜 생성), 수정(`{ id, changes }`), 삭제 구조를 따릅니다.
- **연쇄 삭제**: 글을 삭제하면 같은 slice 안에서 댓글도 함께 지웁니다. 노래를 삭제하면 quotesSlice의 `extraReducers`가 그 action을 듣고 문장을 지웁니다.
- **검색어를 주소에 저장**: `useSearchParams`를 쓰면 뒤로 가기, 새로고침, 링크 공유를 해도 같은 검색 결과가 나옵니다. `useDebounce`로 입력이 멈췄을 때만 주소를 바꿉니다.

## 향후 개선 과제

- 실제 서버와 데이터베이스 연동 (지금은 브라우저 localStorage에만 저장)
- 비밀번호 암호화와 서버 인증 (지금은 학습용으로 평문 저장)
- 이미지 업로드 (앨범 재킷)
- 문장 좋아요와 공유
- 간격 반복(Spaced Repetition) 학습 알고리즘으로 복습 순서 정하기
